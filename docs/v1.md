> **Harmintosh = ArkUI 宿主 + C++ ABI 层 + Rust iOS Runtime，让 ARM64 iOS App 原生执行，并兼容 Darwin / Mach / iOS Framework。**

不是虚拟机，不模拟 ARM64 CPU，也不重写 SwiftUI。

# 4. Rust：Harmintosh 真正的 Runtime Core

Rust 负责大量复杂但不需要直接碰 ABI 的逻辑。

```text
runtime/
├── macho/
├── dyld/
├── process/
├── mach/
├── darwin/
├── xpc/
├── services/
├── vfs/
├── sysroot/
└── diagnostics/
```

例如：

```rust
pub struct Runtime {
    images: ImageManager,
    mach: MachKernel,
    services: ServiceRegistry,
    vfs: VirtualFileSystem,
    processes: ProcessManager,
}
```

然后：

```rust
runtime.launch("/apps/HelloWorld.app")
```

它负责整个 launch 流程。

Rust 很适合这些部分，因为 Mach IPC / service registry / loader 状态非常容易出现：

- use-after-free
- 生命周期混乱
- 并发竞态
- message parser 越界

用 Rust 会舒服很多。

# 5. C++ 和 Rust 之间只走 C ABI

不要搞 C++ 调 Rust CXX 大量模板绑定。

保持非常简单：

```cpp
extern "C" {

HmRuntime* hm_runtime_create(
    const HmRuntimeConfig* config
);

HmResult hm_runtime_launch(
    HmRuntime* runtime,
    const char* app_path
);

void hm_runtime_stop(HmRuntime* runtime);

}
```

Rust：

```rust
#[no_mangle]
pub extern "C" fn hm_runtime_launch(
    runtime: *mut HmRuntime,
    app_path: *const c_char,
) -> HmResult {
    // ...
}
```

这样：

```text
ArkTS
 ↓
C++
 ↓
C ABI
 ↓
Rust
```

非常稳定。

以后 Android 版也直接：

```text
Kotlin
 ↓
JNI
 ↓
同一个 C ABI
 ↓
Rust Core
```

# 21. 一个非常关键的 Gate 0

在真正写几万行代码之前，**第一件事情不是 SwiftUI。**

要验证：

> HarmonyOS Phone 普通 HAP 能不能把自己拥有的 Mach-O 文件映射成 RX 并直接执行其中 ARM64 指令。

因为 HarmonyOS 对可执行内存/JIT/外部可执行文件的限制非常严格；官方开发体系主要支持把 native `.so` 打包进 HAP，动态可执行内存则属于受控能力。[华为开发者](https://developer.huawei.com/consumer/cn/forum/topic/0201204572814790356?utm_source=chatgpt.com)

所以第一天就做：

```text
Gate 0
```

### Test A

HAP resources 中放：

```text
test.bin
```

里面：

```asm
mov x0, #42
ret
```

然后尝试：

```cpp
fd = open(...)
mmap(PROT_READ | PROT_EXEC)
```

执行。

如果：

```text
42
```

回来：

**非常好。**

## 我建议你现在第一行代码都不要写 Loader

先写 **`execution_probe`**。

因为它会决定 Harmintosh 接下来走：

```text

```

还是：

